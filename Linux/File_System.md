## /usr/
Unix System Resources,存放用户级别的系统资源和应用程序。

### /usr/bin/
存放大多数用户命令和可执行文件，比如grep, awk, cutl等

### /usr/sbin/
存放系统管理程序，通常由root用户运行，比如httpd, sshd等。

### /usr/include/
存放 C/C++ 程序编译时需要的头文件。

### /usr/src/
存放源代码，例如 Linux 内核的源代码。

### /usr/local/
该目录通常用于保存用户自行安装的软件和数据，保留那些不是由系统包管理器安装的本地软件和数据。
这个目录结构与 /usr/ 类似，包含 bin/, lib/, share/ 等目录，用于区分由系统包管理器管理的软件和本地编译安装的软件。

#### /usr/local/bin/
存放用户安装的可执行文件，通常是用户手动编译或者手动安装的程序。

#### /usr/local/lib/
存放用户安装的库文件，这些库文件是一些程序所需的支持代码。

#### /usr/local/include/
存放编程语言的头文件，通常用于C或者C++.

#### /usr/local/src/
用于存放源代码，比如那些用来手动编译生成可执行文件的源代码。

#### /usr/local/*/
其他自行安装的工具，比如从官方网站下载的arm-gnu-toolchain等

## /opt/
用于存放"可选的"或"附加的"应用软件包的位置。这个目录主要用于存放第三方商业软件或较大的独立软件包，这些软件包通常是自包含的，也就是说，它们包含了运行应用所需的所有文件，包括二进制文件、库、数据文件和配置文件。比如：

1. 第三方应用程序，这些软件并不是由系统的包管理系统管理的，而是由软件供应商直接提供。例如，一些大型的软件如 Oracle, Google Chrome, Microsoft Teams 等，它们经常安装在 /opt 目录下。
2. 自包含的软件包：软件开发者经常选择将其应用程序打包成一个大的二进制包，并安装在 /opt 下，以避免干扰到系统中的其他文件或依赖关系。比如clone一些开源软件并通过make install安装的软件。

通常，每个安装在 /opt 中的软件应该有自己的子目录，如 /opt/package，package 是指具体的软件包名。例如，如果你安装了 Google Chrome，它可能位于 /opt/google/chrome.

可以通过设置软链接的方法，方便地使用opt文件夹下安装的软件。比如安装了/opt/myapp, 然后创建如下的软链接：
```bash
ln -s /opt/myapp/bin/myapp /usr/local/bin/myapp
```
